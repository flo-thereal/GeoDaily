# GeoDaily — CLAUDE.md

## Project Overview

GeoDaily is a geography learning web application where users complete daily quizzes (flags, capitals, map pinpointing) generated by the Google Gemini AI. It is a single-process monorepo: an Express.js server serves both the REST API and the React SPA, with Vite providing hot-module replacement in development.

The app has two runtime modes:
- **Standalone mode** (no `DATABASE_URL`): Challenge data is ephemeral, held in-memory. A hardcoded set of sample countries is served. Auth is unavailable.
- **Database mode** (`DATABASE_URL` set): Full feature set. PostgreSQL persists challenges, user accounts, stats, achievements, and country progress. A daily challenge scheduler pre-generates Gemini content at UTC midnight.

## Development Commands

### Development & Build

```bash
npm run dev          # Start dev server — serves API + Vite HMR on port 3000
npm run build        # Vite production build → dist/
npm run start        # Production server (serves dist/ as static files)
npm run lint         # TypeScript type check only (tsc --noEmit) — no ESLint
```

### Testing

```bash
npm run test              # Unit tests (Vitest, no server or DB needed)
npm run test:watch        # Unit tests in watch mode
npm run test:ui           # Vitest browser UI
npm run test:api          # API integration tests (server MUST be running first)
npm run test:e2e          # Playwright E2E (auto-starts server)
npm run test:e2e:ui       # Playwright UI mode
npm run test:e2e:headed   # Playwright with visible browser
npm run test:all          # Unit + E2E (does not include API tests)
```

### Database

```bash
npm run db:generate  # Generate a new Drizzle migration from schema changes

npm run db:push      # Push schema directly without migration file (CI / dev shortcut)
npm run db:studio    # Launch Drizzle Studio in the browser
npm run db:seed      # Seed dev user, achievements, and countries
```

```bash

docker compose up --build

docker compose -f docker-compose.prod.yml up -d
```

## Environment Variables

Copy `.env.example` to `.env` and configure:

| Variable | Required | Default | Description |
|---|---|---|---|
| `GEMINI_API_KEY` | Yes | — | Google Gemini API key for quiz generation |
| `DATABASE_URL` | Production only | — | PostgreSQL DSN. Omit to run in standalone (in-memory) mode |
| `JWT_SECRET` | Production only | — | Min 32 chars. Required in production |
| `DEV_AUTH_BYPASS` | Dev only | `false` | Set `true` to skip JWT auth (uses seeded dev user `00000000-0000-0000-0000-000000000001`) |
| `NODE_ENV` | No | `development` | `development` or `production` |
| `APP_URL` | No | — | Hosting URL for self-referential links |
| `PORT` | No | `3000` | Server listen port |

**Production validation**: `server.ts` calls `validateRuntimeConfig()` at startup which throws if `NODE_ENV=production` and `JWT_SECRET` is missing/too short, `DEV_AUTH_BYPASS=true`, `DATABASE_URL` is missing, or `GEMINI_API_KEY` is missing.

**Local dev without Docker**: Set only `GEMINI_API_KEY`. The app runs in standalone mode — no database or JWT needed.

## Code Conventions

### TypeScript

- Strict mode throughout. Run `npm run lint` to verify.
- Target is ES2022, module resolution is `bundler`.
- `@/*` path alias resolves to the **repository root** (not `src/`). Import from both server and client: `@/server/drizzle/index`, `@/src/store/useStore`.
- No raw `any` unless handling untyped external data (Gemini JSON responses, JSONB columns).

### React / Frontend

- **Functional components with hooks only** — no class components.
- **Named exports** for all components (`export function Foo()`, never `export default`). The exception is `App.tsx` which uses `export default` as the Vite SPA entry.
- **Tailwind utility classes exclusively** — no CSS modules, no inline `style` attributes (except Leaflet marker config and font variation settings for Material Symbols icons).
- **`cn()` from `src/lib/utils.ts`** for conditional class merging (wraps `clsx` + `tailwind-merge`).
- **`lucide-react`** for icons. Material Symbols in the nav are rendered via a CDN `<link>` as `<span className="material-symbols-outlined">`.
- **`motion`** (v12, standalone Framer Motion build) for animations. Import from `motion/react`, not `framer-motion`.
- **`canvas-confetti`** for celebration effects on quiz completion.

### State Management

- **Zustand** (`src/store/useStore.ts`) is the single client-side store, persisted to `localStorage` as `geodaily-storage`.
- Store fields: `streak`, `lastPlayedDate`, `points`, `dailyTasks`, `dailyTasksDate`, `currentTaskIndex`, `isDailyCompleted`, `history`.
- Auth token is managed separately by `getAuthToken()` / `setAuthToken()` in `src/services/api.ts`, stored under `geodaily_auth_token`.
- Do not put server-side user data (stats, achievements) in the Zustand store — fetch on demand via the API.

### HTTP Client

- **Always use `apiRequest<T>()`** from `src/services/api.ts`. It handles `Content-Type`, `Authorization: Bearer <token>`, and error unwrapping.
- Pass `{ requireAuth: true }` to throw immediately if no token is present.
- Error responses from the server are always `{ error: string }`. The client unwraps this and throws a plain `Error`.

### Express / Backend

- All routes use the **Express Router** pattern. Each file in `server/routes/` exports `default router`.
- Routers are mounted in `server.ts` via dynamic `import()` only when `DATABASE_URL` is set.
- Protected routes use `authMiddleware` from `server/auth.ts`; routes that optionally identify the user use `optionalAuthMiddleware`.
- Request handlers use the `AuthRequest` type (extends `Express.Request` with `user?: AuthUser`).
- All error responses: `{ error: string }` with appropriate HTTP status codes.

## Database Layer

**ORM**: Drizzle ORM with postgres.js client. Never write raw SQL in route handlers.

Import `db` and table symbols from `server/drizzle/index.ts` (re-exports everything from `schema.ts`).

### Schema — 11 Tables

| Table | Primary Key | Notes |
|---|---|---|
| `users` | `uuid` | `email` is unique; `level` and `title` are display-only |
| `userSettings` | `userId` (FK, 1-to-1) | Created automatically on user registration |
| `userStats` | `userId` (FK, 1-to-1) | Created automatically on user registration |
| `userContinentMastery` | `(userId, continent)` composite | 5 rows per user: Europe, Asia, Africa, Americas, Oceania |
| `dailyChallenges` | `uuid` | `date` (YYYY-MM-DD) is unique; `questions` is a `jsonb` array |
| `userChallengeHistory` | `uuid` | Multiple rows per user; `answers` is `jsonb` (`StoredAnswer[]`) |
| `achievements` | `varchar(50)` slug | Seeded by `db:seed`; IDs are checked in the submit handler |
| `userAchievements` | `(userId, achievementId)` composite | Unlocked at challenge submit time |
| `countries` | `varchar(3)` code | ISO alpha-2/alpha-3; seeded from `server/data/countries.json` |
| `userCountryProgress` | `(userId, countryCode)` composite | `timesCorrect >= 3` sets `mastered = true` |
| `sessions` | `uuid` | JWT strings stored here (validation relies on `verifyToken()`, not DB lookup) |

### Migration Workflow

- Schema changes → edit `server/drizzle/schema.ts` → `npm run db:generate` → commit migration.
- Use `npm run db:push` (no migration file) for rapid local iteration and in CI.
- The Drizzle `db` instance is created with `{ schema }` to enable relational queries.

All routes are prefixed with `/api/` and mounted in `server.ts`.

| Group | Endpoints |
|---|---|

| Scope | Limit | Window |
|---|---|---|
| All `/api/*` | 600 requests | 15 minutes |
| `/users/register`, `/users/login` | 20 requests | 15 minutes |
| `/daily`, `/practice` | 120 requests | 60 minutes |

## Authentication Flow

1. Client calls `POST /api/users/register` or `POST /api/users/login` → receives `{ user, token }`.
2. Client stores the JWT via `setAuthToken()` → `localStorage` key `geodaily_auth_token`.
3. Subsequent requests attach `Authorization: Bearer <token>` via `apiRequest()`.
4. `authMiddleware` verifies the JWT (7-day expiry) and attaches `req.user`.
5. `DEV_AUTH_BYPASS=true` skips JWT entirely and uses the seeded dev user (`00000000-0000-0000-0000-000000000001`, `dev@geodaily.local`). **Never enable in production** — `validateRuntimeConfig()` enforces this.

## Quiz / Challenge Data Model

Each challenge is an array of `DailyTask` objects with three question types:

| Type | Question | `correctAnswer` | `options` | `imageUrl` | `mapCoordinates` |
|---|---|---|---|---|---|
| `flag` | "Which country's flag is this?" | Country name | 4 names | 2-letter ISO code | — |
| `capital` | "What is the capital of X?" | City name | 4 city names | — | — |
| `map` | Place description | Place name | Empty array | — | `{ lat, lng }` |

**Scoring**: 100 points per correct answer. 5 questions × 100 = 500 max. A perfect score requires `score === maxScore && maxScore >= 500`.

**Caching**: Once generated, the challenge is stored in `dailyChallenges` and served directly on subsequent requests. The scheduler (`server/scheduler.ts`) pre-generates today's and tomorrow's challenges at UTC midnight.

**Flag images**: Fetched from `https://flagcdn.com/w80/{code}.png` where `{code}` is the lowercase 2-letter ISO code stored in `task.imageUrl`.

## Testing

### Unit Tests (`tests/unit/`)

- Runner: Vitest, Node environment, no server or DB needed.
- Tests Zustand store actions, scoring/streak logic, API service with mocked `fetch`.
- `localStorage` is simulated with a `MemoryStorage` class defined inline in test files.
- The store uses `persist` middleware that reads `localStorage` at module evaluation time — use `vi.resetModules()` + dynamic `import()` inside `beforeEach` for a clean state per test.

### API Integration Tests (`tests/api/`)

- Runner: Vitest, Node environment, 15s timeout, real HTTP to `http://localhost:3000`.
- **Server must already be running** before executing these tests.
- Creates a fresh user with a timestamped email in `beforeAll` to avoid conflicts.
- Gracefully skips DB-specific assertions when `health.database === 'not configured'`.

### E2E Tests (`tests/e2e/`)

- Runner: Playwright, Chromium only.
- `playwright.config.ts` auto-starts the dev server via `webServer` directive (reuses existing if running).
- Covers: auth flows, quiz interactions, localStorage persistence, profile, settings, atlas.
- Retries: 2 in CI, 0 locally. Workers: 1 in CI (serial), unconstrained locally.
- CI runs only `tests/e2e/persistence.spec.ts` to keep the pipeline fast.

### CI Pipeline (`.github/workflows/tests.yml`)

1. Spins up `postgres:16-alpine` as a service.
2. Runs `npm run db:push && npm run db:seed`.
3. Runs unit tests.
4. Starts dev server in the background, polls `/api/health`, runs API tests.
5. Runs `tests/e2e/persistence.spec.ts`.

CI environment: `DEV_AUTH_BYPASS=true`, `GEMINI_API_KEY=test-key`, `JWT_SECRET=ci_jwt_secret`.

## Gotchas for AI Assistants

**Dual-mode architecture**: When `DATABASE_URL` is absent, `server/routes/` is never imported — those files import from `server/drizzle/index.ts` which would throw at module load time. Always ensure `DATABASE_URL` is set before testing any authenticated or DB-backed endpoint.

**`@/*` alias resolves to the repo root, not `src/`**: `@/server/drizzle/index` is valid from client code and `@/src/store/useStore` is valid from server code.

**Route order in `countries.ts`**: `/meta/regions` is registered before `/:code` to prevent Express matching `"meta"` as a country code. Keep fixed paths before parameterized paths when adding routes.

**`db:push` vs `db:generate`**: Use `db:push` for rapid iteration in dev and CI. Use generate + migrate for production deployments that need a migration history.

**Gemini `test-key` in CI**: Any code path that calls `ai.models.generateContent()` returns an auth error with the placeholder key. Routes return HTTP 401 in that case — tests must handle this gracefully.

**Points vs question counts in `userStats`**: `totalQuestionsAnswered` is incremented by `maxScore / 100` and `correctAnswers` by `score / 100`. Despite the names, these columns store question counts, not raw point totals.

**`userChallengeHistory.answers`**: Stores `StoredAnswer[]` with fields `{ guess, isCorrect, questionType, countryCode }`. The `countryCode` is extracted from `task.imageUrl` (flag tasks) and normalised to uppercase.

**Leaflet icon fix in `MapQuiz.tsx`**: Deletes `L.Icon.Default.prototype._getIconUrl` and re-applies icon URLs via `mergeOptions`. This is a required Vite/Webpack workaround — do not remove it.

**Zustand module reset in tests**: The store's `persist` middleware calls `localStorage.getItem` at import time. Use `vi.resetModules()` + dynamic `import()` in `beforeEach` to reset state between tests.

**No ESLint, no Prettier, no pre-commit hooks**: The only automated gate is `npm run lint` (`tsc --noEmit`). Match the formatting style of surrounding code.

**`motion` package**: Uses v12 (standalone Framer Motion build). Import from `motion/react`, not `framer-motion`.
